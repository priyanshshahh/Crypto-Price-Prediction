# Deploying the dashboard (Vercel, free tier)

The dashboard is a static Vite build. All data comes from `public/data/crypto_data.json`
(generated by `python pipeline.py`), so **no backend, database, or env vars are required**.

## One-time setup

```bash
npm i -g vercel      # or: brew install vercel-cli
vercel login         # opens browser; use your account
```

## Deploy

From the repo root:

```bash
# make sure the dashboard data is fresh (optional but recommended)
.venv/bin/python pipeline.py

# preview deployment (unique URL)
vercel

# production deployment
vercel --prod
```

That's it. `vercel.json` pins the framework (Vite), build command, and output directory,
so the defaults just work. The first `vercel` run will ask to link/create a project —
accept the defaults (scope: your account, project name: crypto-price-prediction).

## Updating the live site with new model results

```bash
.venv/bin/python pipeline.py   # regenerates public/data/crypto_data.json
vercel --prod                  # redeploys the static build
```

## Optional: real Supabase backend

The app auto-detects Supabase credentials. If you want live DB-backed data instead of the
static JSON:

1. Create a Supabase project and run the migration in `supabase/migrations/`.
2. In Vercel → Project → Settings → Environment Variables, add
   `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
3. Redeploy (`vercel --prod`).

Without those vars the app uses the static JSON path — that is the documented default.
